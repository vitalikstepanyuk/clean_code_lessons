# Питання 1. Навіщо структурувати код?  
Варіанти відповідей (виберіть усі правильні варіанти):  
- [ ] а. Структурування коду значно сповільнює розробку - тож зайве  
- [ ] б. Структурований код легше читати і розуміти.  
- [ ] в. Структурований код дозволяє оновлювати або модифікувати частини програми без необхідності редагування всього проекту.  
- [ ] г. Структурування коду допомагає виділити блоки, які можна використовувати у різних частинах вашого проекту або навіть у інших проектах.  
- [ ] ґ. Структурований код легко масштабувати.  

# Питання 2. Що НЕ можна вважати критерієм якості коду?  
Варіанти відповідей (виберіть усі правильні варіанти):  
- [ ] а. Dependability/Надійність  
- [ ] б. Maintainability/Підтримка  
- [ ] в. Coverity/Покриття тестами  
- [ ] г. Efficiency/Ефективність  
- [ ] ґ. Usability/Зручність  
- [ ] д. Code Style/Стиль  
- [ ] е. Simplicity/Простота  
- [ ] є. Brevity/Компактність  

# Питання 3. Чим відрізняються Парадигми, Принципи та Ідіоми програмування?  
Варіанти відповідей (виберіть правильний варіант):  
- [ ] а. Нічим, то тотожні поняття  
- [ ] б. Парадигми пропонують загальні концептуальні підходи; Принципи - правила програмування для підтримки якості; Ідіоми - усталені прийоми, що застосовуються для вирішення конкретних завдань в програмуванні  
- [ ] в. Парадигми - це усталені рамки в індустрії, які не можно порушувати; Принципи -  формують моральний кодекс розробника; Ідіоми - загальновідомі ідеї  
- [ ] г. Парадигми, зазвичай, виключають одна одну; Принципи допомагають з'ясувати вимоги до задач; Ідіоматичні мови програмування максимально наближені до людских  

# Питання 4. Що таке патерн проектування?  
Варіанти відповідей (виберіть правильний варіант):  
- [ ] а. Готовий зразок кода, який можно вставити в свій з мінімальними перетвореннями  
- [ ] б. Іменований опис проблеми та її розвʼязок  
- [ ] в. Обов’язковий інструмент для написання гарного коду  
- [ ] г. Алгоритм розв’язання типових проблем.  

# Питання 5. Для чого потрібно створювати Unit Tests?  
Варіанти відповідей (виберіть НЕ правильний варіант):  
- [ ] а. Забезпечення якості коду і попередження появу дефектів у вихідному коді  
- [ ] б. Для тестування внутрішніх деталей реалізації  
- [ ] в. Підтримка функціональності і рефакторингу - зміни в коді не порушують наявну функціональність та поведінку програми  
- [ ] г. Слугує прикладом, описуючи очікувану поведінку функцій чи класів
